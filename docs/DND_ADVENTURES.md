# Свои приключения D&D для WebSpeak

Игровой стол в канале умеет играть встроенное приключение «Колокол под Сольгардом» и любые приключения, которые администратор загрузит в **Админка → Приключения D&D**. Приключение — это ZIP-архив:

```
my-adventure.zip
├── adventure.json        ← описание приключения (обязательно, в корне или в одной общей папке)
├── images/               ← картинки сцен, карты, портреты (WebP, PNG, JPEG)
└── music/                ← фоновая музыка (OGG/Opus, MP3, M4A, WebM)
```

Папки внутри архива можно называть как угодно: пути к файлам указываются в `adventure.json`. Файлы, которые не упомянуты в `adventure.json`, не сохраняются. Повторная загрузка пакета с тем же `id` заменяет старую версию.

Ограничения: архив до 200 МБ, после распаковки до 300 МБ, до 400 файлов, картинка до 16 МБ, трек до 40 МБ, не больше 30 загруженных приключений. Если сайт стоит за nginx, увеличьте `client_max_body_size` до размера пакета.

## Свои герои игроков

Кроме героев приключения, игроки могут собрать своего героя 1-го уровня в лобби: **Свои герои → Создать героя** (9 рас и 12 классов SRD 5.1, стандартный набор или покупка очков, навыки, портрет из галереи, пара слов о герое). Свой герой подходит к любому приключению, а лист героя по выбору игрока считает шлюз, так что цифры подделать нельзя. Герои хранятся в браузере игрока и, если у игрока есть TeamSpeak-идентичность, на сервере — тогда они доступны на всех его устройствах; кроме того, их можно выгрузить в файл и загрузить обратно.

Ведущий начисляет опыт (карточка «Партия героев»), и свои герои растут до 5-го уровня по правилам SRD: подклассы, увеличение характеристик на 4-м уровне, дополнительная атака, новые ячейки. Готовые герои приключения уровень не повышают. Инвентарь и монеты героя видят он сам и ведущий; ведущий может выдать или забрать предметы.

## Что видят игроки

Шлюз отправляет игрокам приключение без заметок ведущего (`notes`), без текстов для чтения (`intro`, они приходят только когда ведущий нажмёт «Показать игрокам»), без расстановки монстров (`encounter`, `reveal`), без находок (`loot`) и без характеристик монстров (только имя и портрет). Ведущий получает всё.

### Поля верхнего уровня

| Поле | Что это |
| --- | --- |
| `schema` | Всегда `1`. |
| `id` | 3–48 символов: строчные латинские буквы, цифры, дефис. Не может совпадать со встроенным (`solgard-bell`). |
| `title`, `summary` | Название и одна-две фразы для лобби. |
| `level`, `length` | Уровень героев (1–20) и длительность, например «Ваншот · 3 часа». |
| `includeHeroes` | Встроенные готовые герои по id: `ilva`, `osmund`, `mirra`, `tiran`, `grom`. |
| `heroes` | Свои герои (см. ниже). Нужен хотя бы один герой — свой или встроенный. |
| `includeMonsters` | Встроенные монстры SRD по id: `skeleton`, `zombie`, `giant-rat`, `ghoul`, `specter`, `cultist`, `cult-fanatic`. |
| `monsters` | Свои монстры (см. ниже). |
| `music` | Треки: `id`, `title`, `file`. |
| `combatMusic` | id трека, который играет во время боя, пока музыка «по сценам». |
| `scenes` | Сцены по порядку (до 40). |

### Сцена

| Поле | Что это |
| --- | --- |
| `id`, `title` | Обязательны. |
| `art` | Картинка сюжетной сцены (показывается, если нет карты). Лучше 16:9, например 1536×864. |
| `map` | Тактическая карта: `image`, `cols`, `rows` (до 64×64 клеток), `spawn` — клетки, где герои появляются при первом входе. Клетка — 5 футов; картинка растягивается на `cols × rows` клеток, так что делайте её с пропорциями сетки (например 24×16 клеток → 1536×1024 px). Сетку на саму картинку рисовать не нужно. |
| `intro` | Текст для чтения вслух (до 2000 символов). Ведущий видит его в карточке сцены и может показать всем. |
| `notes` | Заметки ведущего: проверки, СЛ, секреты. Игрокам не отправляются. |
| `music` | id трека сцены. |
| `encounter` | Монстры, которые ставятся на карту при первом открытии сцены: `monsterId`, `x`, `y`, `hidden` (спрятан от игроков, пока ведущий не покажет). Только для сцен с картой. |
| `reveal` | Уже открытые от тумана области при первом входе: `[x, y, ширина, высота]` в клетках. |
| `loot` | Находки сцены (до 20): `name`, `qty` (1–999), необязательные `text` (описание, до 300 символов) и `icon` (картинка из пакета или `/dnd/library/items/<id>.webp`). Ведущий выдаёт их героям кнопкой «Выдать» в карточке сцены — предмет попадает в инвентарь с картинкой. Игроки список не видят. |

### Герой

```json
{
  "id": "vera", "name": "Вера", "race": "Человек", "cls": "Следопыт", "level": 1,
  "maxHp": 12, "ac": 14, "speed": 30,
  "abilities": { "str": 12, "dex": 16, "con": 14, "int": 10, "wis": 14, "cha": 8 },
  "saves": ["str", "dex"],
  "skills": ["perception", "stealth", "survival", "athletics"],
  "expertise": [],
  "attacks": [{ "name": "Длинный лук", "bonus": 5, "damage": "1d8+3", "note": "дальнобойная 150/600 фт" }],
  "features": ["Избранный враг: нежить"],
  "equipment": ["Длинный лук, 20 стрел", "Кожаный доспех"],
  "spells": [],
  "story": "Охотится на тех, кто поднимает мёртвых.",
  "portrait": "images/vera.webp"
}
```

Необязательно: `hitDie` — кость хитов (6, 8, 10 или 12, по умолчанию 8; тратится на коротком отдыхе), `resources` — что герой тратит и восстанавливает на отдыхе:

```json
"resources": [
  { "id": "slot1", "name": "Ячейки 1-го круга", "max": 2, "recharge": "long" },
  { "id": "second-wind", "name": "Второе дыхание", "max": 1, "recharge": "short" }
]
```

Атака со спасброском (заклинание, дыхание) пишется с `"bonus": null` и полем `save`: `{ "ability": "dex", "dc": 13, "half": true }` (`half` — половина урона при успехе). Тогда в игре у неё появляется кнопка «Спасбросок»: выбрать цели, и шлюз сам бросит урон, спасброски всех целей и нанесёт урон.

Характеристики: `str`, `dex`, `con`, `int`, `wis`, `cha`. Навыки: `acrobatics`, `animalHandling`, `arcana`, `athletics`, `deception`, `history`, `insight`, `intimidation`, `investigation`, `medicine`, `nature`, `perception`, `performance`, `persuasion`, `religion`, `sleightOfHand`, `stealth`, `survival`. Бонусы навыков, спасбросков и инициативы стол считает сам по правилам 5e (бонус мастерства по уровню, `expertise` удваивает его).

### Монстр

`id`, `name`, `cr` (как в книге, например `"1/4"`), `maxHp`, `ac`, `speed`, `dex` (значение Ловкости, для инициативы), `saves` (бонусы спасбросков, например `{ "wis": 2 }`; не указанные — 0, Ловкость — по `dex`), `attacks` (как у героя; `bonus: null` — атака без броска попадания, например заклинание со спасброском), `traits` (строки), `portrait`.

Урон пишется как обычный бросок: `1d6+2`, `2d8`, `1d10+1d6+3`. Можно `к` вместо `d`.

## Как собрать пакет

1. Сложите `adventure.json` и файлы в одну папку.
2. Упакуйте её содержимое (или саму папку) в ZIP любым архиватором.
3. Загрузите в **Админка → Приключения D&D**. Если в пакете ошибка, админка покажет, в каком поле она, например `scenes[2].map.image: file "images/crypt.webp" is not in the package`.

## Картинки и музыка

Встроенное приключение нарисовано в ComfyUI моделью Z-Image Turbo (карты 1536×1024, сцены 1536×864, портреты 768×768 → 256×256 WebP), а музыка сгенерирована ACE-Step 1.5 XL Turbo (2 минуты, инструментал, зациклена и пережата в Opus 96 кбит/с). Для карт хорошо работают подсказки вида «Top-down tabletop RPG battle map, orthographic view from directly above, hand-painted…, no grid lines, no text, no people».

## Конструктор приключений

Приключение можно собрать без ZIP-файла — в браузере. Администратор на странице **D&D-приключения** создаёт ссылку конструктора (`/create/<токен>`) и отправляет её автору. Автор открывает ссылку, называет себя, администратор одобряет его браузер — и дальше автор по той же ссылке создаёт и правит приключения: черновики сохраняются на сервере сами, к ним можно вернуться в любой момент. В конструкторе есть библиотека: 75 монстров SRD с характеристиками, 30 NPC (трактирщица, кузнец, рыцарь, маг, пираты… — с характеристиками NPC из SRD), 51 боевая карта от 10×10 до 32×24 клеток (с фильтром по размеру), 15 картинок сцен, 62 предмета и 100+ портретов героев; есть библиотека из 30 зацикленных треков (места, настроения, бой); можно загрузить свои картинки и музыку. В игре ведущий может включить любой трек библиотеки в любом приключении — из меню музыки в шапке стола. Кнопка «Опубликовать» проверяет черновик и устанавливает его как обычный пакет (`ed-<id>`), повторная публикация заменяет ту же версию.
